# Type Casting in Java

## 1. What Is Casting?

Casting creates an intermediate expression with a different type from the original expression. The resulting value is usually approximately the same as the original, although some casts preserve the value exactly.

The syntax places the target type in parentheses before the expression:

```java
(int) 3.2
```

Here, `3.2` is a `double`. Casting it to `int` produces the value `3`, because the fractional part is discarded.

Casts can serve several purposes:

- **Change a primitive expression's type:** Create an expression with a different primitive type.
- **Specialize a reference expression's type:** Cast a reference to a more specific type in the class hierarchy. This can fail at runtime.
- **Specify a lambda expression's target type:** Use a cast to tell the compiler which functional interface the lambda should implement.

## 2. Primitive Casting and Loss of Information

Primitive casts can change how a numeric value is represented. When casting to a smaller type, some bits may be discarded, producing a result that differs significantly from the original value.

For example, consider casting the integer `999` to a `byte`:

```java
int value = 999;
byte result = (byte) value;

System.out.println(result); // -25
```

A `byte` uses 8 bits. When `999` is narrowed to a `byte`, only the least significant 8 bits are retained. Those bits represent `-25` as a signed byte.

The result may appear nonsensical if you expected the original numeric value to be preserved. This matters particularly when performing arithmetic with values that do not fit into the target type.

**Remember:** A primitive cast can change the value, not merely its declared type.

## 3. Casting References in a Class Hierarchy

Reference casts depend on the relationship between the types and the actual object being referenced.

### Downcasting

A downcast moves from a parent type to a more specialized subtype.

```java
Animal animal = new Dog();
Dog dog = (Dog) animal;
```

The cast succeeds because the actual object is a `Dog`.

However, if the referenced object is not an instance of the target type, the cast fails at runtime with a `ClassCastException`.

```java
Animal animal = new Cat();
Dog dog = (Dog) animal; // ClassCastException at runtime
```

The compiler may permit a downcast even though its success depends on the actual object at runtime.

### Upcasting

An upcast moves from a subtype to a parent type.

```java
Dog dog = new Dog();
Animal animal = (Animal) dog;
```

This is valid because a `Dog` is also an `Animal`. The cast is unnecessary because Java can perform this conversion implicitly, but explicitly writing it is still valid.

An IDE may warn that the cast is redundant.

### Casting Between Unrelated Classes

A cast across a class hierarchy between unrelated classes is rejected at compile time when the classes have no possible subtype relationship.

The reason is that neither class can be treated as an instance of the other through inheritance.

## 4. Casting and Interfaces

Interface casts follow different rules from casts between classes.

A cast involving an interface may be permitted even when the class does not currently implement that interface. Unless the class is `final`, a subclass could potentially implement the interface.

For example:

```java
class Animal {
}

interface Swimmable {
}

Animal animal = new Animal();
Swimmable swimmable = (Swimmable) animal;
```

The compiler can permit this cast because a subclass of `Animal` could implement `Swimmable`. However, this particular cast fails at runtime because the actual object is a plain `Animal`, which does not implement `Swimmable`.

**Important distinction:** A cast being accepted by the compiler does not guarantee that it will succeed at runtime.

## 5. Casting Lambda Expressions

A lambda expression's type is determined by its context. The compiler uses the target functional interface to understand the lambda's parameters and return value.

For example:

```java
Predicate<String> predicate = s -> s.length() > 3;
```

The assignment context tells the compiler that the lambda implements `Predicate<String>`.

A cast can also provide the target type:

```java
var predicate =
    (Predicate<String>) (s -> s.length() > 3);
```

Here, the cast tells the compiler that the lambda should implement `Predicate<String>`. It is not converting an already existing lambda object into a more specialized type; it is providing the target type needed to interpret the lambda expression.

## 6. Exam Distinctions

| Casting scenario | Main rule |
|---|---|
| Primitive cast | Can change the value or lose information |
| Downcast | May compile but fail at runtime |
| Invalid reference cast | Can throw `ClassCastException` |
| Upcast | Valid and generally unnecessary explicitly |
| Cast between unrelated classes | Rejected at compile time when no class-hierarchy relationship is possible |
| Interface cast | May compile even if the actual object cannot satisfy it |
| Lambda cast | Can specify the lambda's target functional interface |
