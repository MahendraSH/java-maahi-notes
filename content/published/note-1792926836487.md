# Java Operators — Part 1

## Overview

This lesson introduces Java operators and focuses on the rules that determine how expressions are evaluated.

The main topics are operator precedence, L-values, side effects, operand evaluation order, increment and decrement operators, shift operators, logical operators, and assignment expressions.

## 1. Operator Precedence

Operator precedence determines which operators are applied first when an expression contains multiple operators.

For example, multiplication, division, and remainder have higher precedence than addition and subtraction.

```java
int result = 10 + 4 * 3;
System.out.println(result); // 22
```

Multiplication is evaluated before addition, so the result is 22 rather than 42.

The instructor notes that precedence questions are not a major focus of the exam, but familiarity with the key rules is useful.

## 2. Important Java Operators

### Increment and Decrement

Java provides pre-increment, post-increment, pre-decrement, and post-decrement operators.

| Operator | Meaning |
|---|---|
| `++i` | Increment `i` before producing the expression's value |
| `i++` | Produce the original value before incrementing `i` |
| `--i` | Decrement `i` before producing the expression's value |
| `i--` | Produce the original value before decrementing `i` |

### Unary Operators

- Unary plus (`+`) indicates a positive numeric value.
- Unary minus (`-`) negates a numeric value.
- Bitwise complement (`~`) inverts the bits of an integer.
- Logical complement (`!`) negates a Boolean value.

Bitwise complement operates on integer values, while logical complement operates on Boolean values.

### Arithmetic Operators

The main arithmetic operators are:

- Multiplication (`*`)
- Division (`/`)
- Remainder (`%`)
- Addition (`+`)
- Subtraction (`-`)

The remainder operator returns the remainder from integer division when used with integer operands. The instructor highlights it as a topic worth examining in more detail.

### Shift Operators

Java has three shift operators:

- Left shift (`<<`): shifts bits to the left.
- Signed right shift (`>>`): shifts bits to the right while preserving the sign.
- Unsigned right shift (`>>>`): shifts bits to the right and fills the leftmost positions with zeros.

Ignoring overflow, a left shift by one position often corresponds to multiplication by two. A signed right shift by one position often corresponds to division by two for positive integers, with fractional parts discarded.

The unsigned right shift does not preserve the sign bit. Applying it to a negative integer can produce a positive result.

### Comparison and Type Testing

Java provides relational operators:

- Less than (`<`)
- Greater than (`>`)
- Less than or equal to (`<=`)
- Greater than or equal to (`>=`)

The `instanceof` operator tests whether an object is compatible with a specified reference type.

```java
Object value = "Java";

System.out.println(value instanceof String); // true
```

The type on the right side of `instanceof` is a type expression, not a variable containing a type name.

### Equality Operators

Java provides two equality operators:

- `==` tests equality according to the operand types. For references, it tests whether the references identify the same object.
- `!=` tests inequality.

The instructor identifies equality as an important topic that will be explored in more detail later.

### Bitwise and Logical Operators

Java includes bitwise AND (`&`), XOR (`^`), and OR (`|`), along with logical AND (`&&`) and logical OR (`||`).

The double-character logical operators are short-circuit operators. They can skip evaluation of the right operand when the result is already determined by the left operand.

### Conditional and Assignment Operators

The conditional operator (`?:`) provides an expression-based alternative to choosing between two results.

Assignment operators have the lowest precedence in the operator hierarchy discussed in this lesson. An assignment is also an expression with a value.

## 3. Expressions and L-Values

An expression has a value and a type. Some expressions also designate a storage location that can be assigned to.

Consider these examples:

```java
int result = 2 + 3;
int[] numbers = {10, 20, 30, 40};

numbers[3] = 99;
```

The expression `2 + 3` produces a value but does not designate a storage location.

The expression `numbers[3]` designates an array element and can be assigned a new value.

An **L-value**, as described by the instructor, is an expression that can appear on the left side of an assignment because it identifies a writable storage location.

## 4. Side Effects

A side effect occurs when evaluating an expression changes program state, such as modifying a variable.

Assignment and increment or decrement operations can produce side effects.

### Pre-Increment

Pre-increment changes the variable before the expression produces its value.

```java
int i = 98;
System.out.println(++i); // 99
```

The variable is incremented first, so the expression evaluates to 99.

### Post-Increment

Post-increment produces the original value before applying the increment.

```java
int i = 98;
System.out.println(i++); // 98

System.out.println(i);   // 99
```

The first expression produces 98. Afterward, the variable contains 99.

### Increment Expressions Are Not L-Values

Although `i` is an L-value, `++i` is an expression rather than an assignable storage location.

```java
int i = 5;

// ++(++i); // Does not compile
```

The outer increment cannot be applied because the result of the inner increment is not an L-value.

## 5. Order of Operand Evaluation

Java evaluates operands from left to right before applying the operation. Side effects occur as the relevant operands are evaluated.

This matters when an operand modifies a variable that another part of the expression depends on.

Consider the following example:

```java
int x = 1;

try {
    System.out.println(100 / --x);
} catch (ArithmeticException e) {
    System.out.println("bang");
}

System.out.println(x);
```

Evaluation proceeds as follows:

1. The left operand, `100`, is evaluated.
2. The right operand, `--x`, is evaluated. The value of `x` becomes zero.
3. The division attempts to divide 100 by zero, throwing an `ArithmeticException`.
4. The exception handler prints `bang`.
5. The final statement prints `0`.

Output:

```text
bang
0
```

The important point is that the decrement occurs before the division is attempted. The exception does not undo the variable's side effect.

## Key Exam Concepts

- Multiplication, division, and remainder have higher precedence than addition and subtraction.
- Pre-increment produces the updated value; post-increment produces the original value.
- An expression can have a value and type without designating writable storage.
- Side effects can change variables during expression evaluation.
- Java evaluates operands from left to right.
- An exception does not automatically reverse side effects that have already occurred.
- `&&` and `||` use short-circuit evaluation.
- `instanceof` checks an object's compatibility with a specified type.
