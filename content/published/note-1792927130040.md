# Numeric Promotions and Conditional Expression Types

## 1. Numeric Promotions

Java performs arithmetic using the primitive numeric types `int`, `long`, `float`, and `double`. Operands with smaller types or different types may be promoted to a wider type before an operation.

Promotion creates a temporary value of another type. It does not change the original variable.

```java
byte b = 10;
short s = 20;

var result = b + s;

System.out.println(result); // 30
// The type of b + s is int.
```

Even though both operands are smaller than `int`, ordinary arithmetic promotes them to `int`.

When operands have different numeric types, the result follows Java's binary numeric promotion rules. For example, an `int` combined with a `long` produces a `long` result.

## 2. Assignment Compatibility and Constant Expressions

Java generally rejects assignments that may lose information. However, a special rule allows certain constant expressions of type `int` or smaller to be assigned to narrower integral types when their values fit within the target type's range.

This exception applies to eligible constant expressions, not arbitrary variables.

```java
byte a = 99;           // Compiles: constant fits in byte

final int x = 99;
byte b = x;            // Compiles: x is a constant variable

int y = 99;
byte c = y;            // Does not compile: y is not final
```

Even though `y` currently contains 99, the compiler does not treat this ordinary variable as a constant expression.

A `long` constant does not qualify for this special narrowing rule, even when its value fits into a `byte`.

```java
final long value = 99L;
byte b = value; // Does not compile
```

### Integral Type Ranges

| Type | Range |
|---|---|
| `byte` | -128 to 127 |
| `short` | -32,768 to 32,767 |
| `char` | 0 to 65,535 |
| `int` | -2³¹ to 2³¹ - 1 |
| `long` | -2⁶³ to 2⁶³ - 1 |

These ranges are important when determining whether a constant expression can be assigned to a narrower type.

## 3. The Conditional Operator and Its Type

The conditional operator (`?:`) selects one of two expressions based on a Boolean condition.

```java
int result = true ? 10 : 20;

System.out.println(result); // 10
```

The type of a conditional expression depends on the types of its second and third operands.

### Identical Operand Types

If both result expressions have the same type, the conditional expression has that type.

### Boolean Conditional Expressions

When the result expressions are Boolean values or wrappers, Java determines whether the result is a primitive `boolean` or a reference type.

For example, combining a primitive `boolean` with a `Boolean` wrapper can result in a primitive `boolean`, requiring unboxing of the wrapper.

### Numeric Conditional Expressions

If the result expressions are numeric, Java determines a compatible numeric type. Unlike ordinary arithmetic promotion, the conditional operator has special rules that can preserve narrower types.

```java
short s = 10;

var result = true ? 3 : s;

// The type of result is short.
```

The integer constant `3` fits into a `short`, so the conditional expression has type `short`.

Another example:

```java
byte b = 127;
short s = 10;

var result = true ? b : s;

// The type of result is short.
```

Both alternatives fit into a `short`, so the result type is `short`.

A constant variable of type `int` can also participate in this narrowing behaviour when its value fits into the other operand's type.

```java
final int x = 10;
byte b = 20;

var result = true ? x : b;

// The type of result is byte.
```

However, a constant variable of type `short` is not automatically narrowed to `byte` under the same rule.

```java
final short s = 10;
byte b = 20;

var result = true ? s : b;

// The type of result is short.
```

**Exam distinction:** Constant-expression narrowing in conditional expressions has specific rules. Do not assume that every constant value is narrowed to the smallest possible type.

### Numeric Wrapper Types

When both alternatives are numeric wrapper types, the conditional expression may unbox them and perform numeric promotion.

```java
var result = true
        ? Double.valueOf(3.1)
        : Integer.valueOf(3);

// The type of result is double.
```

The `Integer` value is unboxed and promoted to `double` to match the other numeric alternative.

## 4. Reference Types in Conditional Expressions

When the conditional alternatives are reference types, Java determines a compatible reference type based on their common supertypes.

If two classes share a common parent class, that parent may be the result type.

```java
class A {}
class B extends A {}
class C extends A {}

B b = new B();
C c = new C();

var result = true ? b : c;

// The inferred type is A.
```

### Shared Interfaces

The resulting reference type may include shared interfaces as well as a common superclass.

For example, if two classes both extend `A` and implement interface `E`, their conditional expression may have a type that incorporates both `A` and `E`.

Some inferred intersection types can be used by the compiler even though they cannot be written directly as ordinary variable declaration types.

The same principle applies to `String` and `StringBuilder`: both implement `CharSequence`, `Comparable`, and `Serializable`. A conditional expression involving them can have an inferred intersection type representing these shared interfaces.

## 5. Primitive Values and Reference Types

If a conditional expression combines a primitive value with a reference alternative, boxing may be required.

```java
var result = true ? 3 : "Java";
```

The primitive `3` is boxed to an `Integer`. The resulting expression has a reference type compatible with both alternatives, such as `Object`.

This differs from a numeric conditional expression, where unboxing and numeric promotion may be applied.

## 6. Switch Expression Types

Switch expressions follow similar type-determination principles to conditional expressions.

- If all result expressions have the same type, that type is used.
- If all alternatives are Boolean, the result can be primitive `boolean`.
- If all alternatives are numeric, Java determines a compatible numeric type.
- If the alternatives are reference types, Java determines a compatible reference type.
- Primitive alternatives may be boxed when the overall result requires a reference type.

```java
int value = 2;

var result = switch (value) {
    case 1 -> 10;
    case 2 -> 20;
    default -> 30;
};

// The type of result is int.
```

### Null in Conditional and Switch Expressions

In a conditional expression, when one branch is `null` and the other is a reference expression, the result type is determined by the reference expression.

Switch expressions can also combine `null`, reference types, and boxed primitive values. Java determines a compatible result type from the alternatives.

The instructor demonstrates that the resulting type can include shared interfaces, not merely a common superclass. In one example involving `String`, `null`, and a boxed numeric result, the inferred type includes `Serializable` and `Comparable`.

## Key Distinctions

- Ordinary arithmetic promotes `byte`, `short`, and `char` operands to `int`.
- Certain constant expressions can be narrowed during initialization if their values fit.
- The conditional operator has special numeric typing rules that differ from ordinary arithmetic promotion.
- Numeric conditional expressions can unbox wrappers and promote values.
- Reference conditional expressions can infer common classes and interfaces.
- Switch expressions determine their result type using similar principles.
